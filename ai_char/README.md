# Раскачка персонажа AI__ (отдельно от основного бота)

Это отдельный, независимый набор скриптов для прокачки нового персонажа **AI__**
на lbast.ru. Использует ту же проверенную боевую/квестовую логику, что и
`daily_quests_piraty.js` (main бот), но:

- работает в **своём** профиле браузера (`ai_char/chrome-profile-ai-char/`),
  создаваемом автоматически при первом запуске — отдельная сессия/куки,
  никак не пересекается с профилем основного персонажа;
- логинится под **другим** игровым аккаунтом (см. учётные данные ниже);
- НЕ запускает `manager_bot.js`/Telegram — чистый Node-скрипт без сторонних
  зависимостей кроме тех, что уже стоят в `package.json` корня репозитория.

**Основного персонажа (Tsunami) эти скрипты вообще не касаются** — они не
импортируют и не запускают `manager_bot.js`/`daily_quests_piraty.js`
напрямую, только копию переиспользуемых функций (`module.js`).

## Учётные данные AI__

Пароль **не хранится в коде** — скрипты требуют переменные окружения
`AI_LOGIN` и `AI_PASS` (сам логин и пароль тебе отдельно, они уже есть
в переписке/памяти этой сессии). Ник персонажа — `AI__`.

Проще всего создать файл `.env` в корне репозитория (он уже в
`.gitignore`, в git не попадёт):

```
AI_LOGIN=твой_числовой_логин
AI_PASS=твой_пароль
```

и подгрузить его перед запуском (например через пакет `dotenv`, который
уже есть в зависимостях корня):

```bash
node -r dotenv/config ai_char/driver.js
```

Либо просто задать переменные в терминале перед запуском (см. ниже).

## Установка (один раз)

Из корня репозитория (там же, где `package.json` основного бота):

```bash
npm install
npx playwright install chromium
```

## Запуск

`check.js` и `verify_last_fight.js` не логинятся сами — используют уже
сохранённую сессию в `ai_char/chrome-profile-ai-char/` (создаётся первым
запуском `driver.js`). `driver.js` логинится сам, если сессии ещё нет —
для него обязательны `AI_LOGIN`/`AI_PASS`.

```bash
# Первый запуск — залогинится и создаст локальный профиль браузера:
AI_LOGIN=... AI_PASS=... AI_MAX_CYCLES=3 node ai_char/driver.js

# Дальше сессия сохранена, можно без пароля:
node ai_char/check.js
node ai_char/verify_last_fight.js
AI_MAX_CYCLES=3 node ai_char/driver.js   # тоже сработает без пароля, пока сессия жива
```

По умолчанию скрипты открывают браузер видимо (`headless: false`), чтобы
можно было смотреть, что происходит. Для фонового запуска поменяй
`headless: false` на `true` в нужном скрипте.

## ГЛАВНЫЙ ПРИНЦИП — всегда проверять исход боя

**"Бой завершен!" в игре НЕ означает победу.** Ничья и поражение выглядят
так же, но не засчитывают прогресс квеста. `fightLoop()` в `module.js`
не проверяет исход сам — после каждого важного боя нужно явно смотреть
`log_infa.php?blogin=AI__&mod=battlesList` (см. `verify_last_fight.js`) —
искать "выбывает из строя" (у кого) и "Ничья!" в шапке лога.

Подробный разбор механик, багов и уроков по этому персонажу — в
`../LESSONS_AI_CHAR.md` в корне репозитория. Читай его перед тем, как
писать новую автоматизацию для AI__ — там уже задокументированы:
- какой контент доступен без коня (до 4 уровня);
- как правильно брать гильдейские квесты;
- баг с "Амулет" (латинская `A` в верстке сайта);
- как пересобирать статы (`pers.php?mod=stats&go=cleanStats&ok=1`,
  сначала снять всю экипировку);
- и другие практические детали.

## Структура

| Файл | Назначение |
|------|-----------|
| `module.js` | Копия переиспользуемых функций из `daily_quests_piraty.js` (бой, квесты, парсинг статов) + доп. экспорты (`progressLifeTreeQuest`, `progressFisherFoodQuest`, `resetToQuestMenu`), которых не было в основном экспорте. |
| `driver.js` | Логин + цикл `runDailyQuests` (N раз, `AI_MAX_CYCLES`). |
| `check.js` | Разовая проверка HP/статов без действий. |
| `verify_last_fight.js` | Проверка исхода последнего боя по логу. |
